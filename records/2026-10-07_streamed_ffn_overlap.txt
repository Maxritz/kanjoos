#   Still ONE LAYER (layer 0) of one model, same job as Phase 33. What this
#   record adds: a measured decomposition of the Phase-33 gap into (a) a
#   host-side allocation trap (hipHostMalloc/hipHostFree per staging buffer),
#   (b) serialisation, and (c) device stream time; and the measured effect of
#   fixing (a) and (b) under three controlled configurations. What it does

#   unexercised (vacuous deadline, stated again below).

# host      : Windows 11, 32 threads
# device    : AMD Radeon RX 9070 XT, gfx1201, RDNA4, wave32, 15.92 GiB, 8 MiB L2

# job       : build/q4k/layer00.job   (layer 0: gate/up Q4_K, down Q6_K, real router)
# tokens    : 512 (1024 routed pairs, top-2 of 4 experts)
# slots     : 2 x 2.4609375 MiB (slot pool 4.922 MiB = 21.1% of the 23.344 MiB bank)
#
# The three configurations, one variable apart:
#   0 serial/churn   = Phase 33 behaviour exactly: 1 item in flight, staging
#                      hipHostMalloc'd before every read, hipHostFree'd on drop
#   1 serial/reuse   = staging pooled and reused (C7's pre-registered bounce
#                      buffers), pool pre-registered before the timed window
#   2 overlap/reuse  = additionally NSLOTS=2 items in flight, demand runs 2
#                      ahead of compute; retire is drain-based, not serialised
#
# Traps added (all MEASURED, all still in the driver):
#   NvmeReader::busy_ns_       reader-thread fread time, queue waits excluded
#   HipTransfer::h2d_ns_       H2D submit -> first DONE poll (host-visible latency)
#   PinnedArena::host_alloc_ns_ / host_free_ns_   pin/unpin cost inside the arena
#   RunStats wait buckets      host spin time, attributed by the object's state
#
# Build line (unchanged from Phase 33):
#   hipcc --rocm-path="G:/ROCM10RT-gfx1201/lib/llvm" -std=c++17 -O2 \
#     --offload-arch=gfx1201 \
#     -Xclang -target-feature -Xclang +wavefrontsize32 \

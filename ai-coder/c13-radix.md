# Worksheet — C13 Radix KV index

**What it owns:** prefix reuse across requests and across turns.

**Why it exists (from `02-components.md` — C13 section; `01` §6):** the radix tree (block-granular, chunked-hash-tree leaves to keep lookups O(1)) maps a token prefix to a list of shared, immutable, refcounted KV blocks.
  The cache key is I5 in full (model fingerprint, arch, dtype, layout, RoPE config, tokenizer, attention implementation version — anything not in the key is not a key). The chunked hash tree (not a naive trie walk) is the lesson from Feather/CHT:
  tree-traversal CPU cost is comparable to the GPU work it saves in a small engine, so cheap lookup matters more than an elegant structure. Hybrid models (gated-delta-net stacks) cannot roll a recurrent state back to an arbitrary prefix —
  so the index stores the token-addressable KV only, and the session path replays a bounded suffix into the recurrent state (the Tail-Replay shape), and hybrid layers are flagged in the index so a rollback request on a hybrid model returns "replay suffix", never "impossible".

  rather than refusing), Acceptance criteria (concurrent sessions share prefixes and produce identical shared-span logits; a cache page from a different model/config/codec is rejected, not misread).

**Interface (from `02-components.md` C13, simplified):**
* Input: a token prefix (from a request/session). Output: a list of shared, immutable, refcounted KV block ids (the blocks that cover the prefix), plus the uncovered suffix (the tokens not in any cached block — to be prefill'd).
* Cache key (I5 in full): model fingerprint + arch + dtype + layout + RoPE config + tokenizer + attention implementation version + KV codec + impl-version. Anything not in the key is not a key.
* Block identity: content-hashed over (model fingerprint, block size, canonical token ids, position offset). A hit returns a shared, immutable, refcounted KV block list — several live sessions pointing at the same block.

**The chunked-hash-tree rationale (verbatim `02-components.md` C13):** "Chunked hash tree, not a naive trie walk: the Feather/CHT lesson is that tree-traversal CPU cost is comparable to the GPU work it saves in a small engine. Cheap lookup matters more than an elegant structure."

**The hybrid-model Tail-Replay (verbatim `02-components.md` C13):** hybrid models (gated-delta-net stacks) cannot roll a recurrent state back to an arbitrary prefix. Where a model has recurrent layers, the index stores the token-addressable KV only, and the session path replays a bounded suffix
  into the recurrent state — the Tail-Replay shape, which is the principled version of the fallback the current code already warns about. Hybrid layers are flagged in the index so a rollback request on a hybrid model returns "replay suffix", never "impossible".

**Acceptance test (verbatim "done when"):**
* A repeated-prefix benchmark shows TTFT reduction proportional to shared prefix length.
* Two concurrent sessions sharing a prefix produce identical logits on the shared span.

**Gates:**
* Depends on C9 (residency — C13's KV block ids are resolved through C9's residency table: a block id maps to VRAM/RAM/NVMe via C9; C13 is the logical→block-id side, C9 is the block-id→location side), C11 (transfer — the physical blocks are moved by C11; C13's block list is what C9/C11 act on),
  C14 (KV cache — C13's blocks are the paged KV blocks; C14 owns the block tables and the physical blocks; C13 is the prefix→block-id mapping, C14 is the block-id→physical-block side), C21 (telemetry — the TTFT reduction and the shared-span logit identity are C21 numbers; the "repeated-prefix benchmark shows the TTFT win" is a C21 result),
  C22 (budget — the KV block size and layer slab come from C22's profile; C13's block-granularity is what C22 sets), C24 (platform — the NVMe store for admitted KV is C24's mechanism; C13's admitted-KV persistence goes through C12/C11/C24).
* The "two concurrent sessions sharing a prefix produce identical logits on the shared span" gate is the bit-identity proof for the radix cache. A coder must be able to run two sessions that share a prefix (one starts first and populates the cache; the second hits the cached blocks) and assert the shared-span logits are identical
  (bit for bit, or within the KV codec's tolerance if a lossy codec is admitted — but the default is bit-identical, because tier movement is I7 and the storage codec is lossless by default; a lossy codec is a declared precision reduction, priced and recorded per page). This is the proof that prefix reuse is correct, not just fast.
* The "repeated-prefix benchmark shows TTFT reduction proportional to shared prefix length" gate is the performance proof. A coder must be able to run a benchmark where the prefix length is varied and the TTFT reduction tracks the shared prefix length (more shared prefix → more cached blocks → lower TTFT), and report it (C21). A coder must not claim a TTFT win without measuring it against a no-prefix baseline.
* The hybrid-model Tail-Replay gate: a coder must implement the "replay suffix" path for hybrid models (replay a bounded suffix into the recurrent state) and flag hybrid layers in the index, so a rollback request on a hybrid model returns "replay suffix" (a real, handled outcome) rather than "impossible" (a refusal that should not happen). A coder must not pretend hybrid models can be rolled back to an arbitrary prefix — they cannot; the recurrent state is the problem, and the Tail-Replay shape is the principled handling.

**Coder notes / pitfalls:**
* The cache key is I5 in full — model fingerprint + arch + dtype + layout + RoPE config + tokenizer + attention implementation version + KV codec + impl-version. A coder must not build a cache key that omits any of these (e.g. omitting the KV codec would let an FP8 block be read as BF16, which is wrong;
  omitting the model fingerprint would let a block from a different model be read, which is wrong). The "a cache page from a different build is not readable" invariant is enforced by the key — a block whose key does not match the current request's key is not a hit, it is a mismatch, and must be rejected, not misread.
* The chunked-hash-tree is the structure, not a naive trie. A coder must implement the chunked-hash-tree (or an equivalent with O(1) lookups and low traversal CPU) — a naive trie walk is the failure mode the Feather/CHT lesson warns about (tree-traversal CPU cost comparable to the GPU work it saves).
  The point is cheap lookup — O(1) block-id resolution per prefix node, not a deep walk. A coder must measure the lookup CPU and ensure it is small relative to the TTFT win (the "cheap lookup matters more than an elegant structure" rule).
* Blocks are content-hashed over (model fingerprint, block size, canonical token ids, position offset). A coder must compute the block hash from these, so that two requests with the same prefix (same token ids, same positions) produce the same block hash and share the block. A coder must not use a non-canonical token representation (e.g. a tokenized form that differs by request) as the block key — the canonical token ids are what make two requests with the same prefix share a block.
* Blocks are shared, immutable, refcounted. A coder must implement refcounting so that a block shared by several sessions is not evicted/reloaded while any session uses it (the refcount is what makes it "shared and immutable" — a block with refcount > 0 is not evictable). A coder must not evict a shared block while a session still uses it (that breaks the "concurrent sessions share prefixes and produce identical shared-span logits" invariant — the second session would miss).
* The hybrid-model Tail-Replay is the handling for recurrent layers. A coder must flag hybrid layers in the index (so C13 knows which layers are token-addressable KV and which are recurrent state), store the token-addressable KV only for hybrid models, and implement the bounded-suffix replay for the recurrent state on rollback.
  A coder must not store recurrent state as if it were token-addressable KV (it is a fixed-size state per layer with its own budget and residency, and is not paged — `04` §6) and must not pretend a hybrid-model rollback is a full prefix rollback (it is a replay of a bounded suffix into the recurrent state).
* The "TTFT reduction proportional to shared prefix length" must be measured, not assumed. A coder must run a repeated-prefix benchmark with varying prefix lengths and report the TTFT reduction per prefix length (C21), and assert the reduction tracks the shared prefix length (more shared prefix → more cached blocks → lower TTFT). A coder must not claim a TTFT win without this measurement, and must not claim a win that does not track prefix length (that would be a wrong conclusion — the win must come from the cached blocks, which scale with prefix length).

**Worked micro-example (host, sanity-check before device):**
Implement a fake C13 with a chunked-hash-tree (or equivalent O(1)-lookup structure), content-hashed blocks (keyed by model fingerprint + block size + canonical token ids + position offset), refcount-based sharing, and a hybrid-model flag with a bounded-suffix replay. Then: (1) insert a prefix (canonical token ids + positions) as a set of blocks, compute each block's content hash, and assert a second request with the same prefix hits the same blocks (same content hash) and gets a refcounted shared block list — the content-hash + sharing gate; (2) assert a request whose key does not match (different model fingerprint, or different KV codec, or different token ids) does not hit (it is a mismatch, rejected, not misread) — the I5 key gate; (3) assert concurrent sessions sharing a prefix produce identical logits on the shared span (bit-identical, or within tolerance if a lossy codec is admitted — but the default is bit-identical) — the shared-span-logit-identity gate; (4) run a repeated-prefix benchmark with varying prefix lengths and assert the TTFT reduction tracks the shared prefix length (more shared prefix → more cached blocks → lower TTFT), reported (C21) — the TTFT-reduction-proportional-to-prefix-length gate; (5) assert a hybrid-model prefix (with recurrent layers flagged in the index) cannot be rolled back to an arbitrary prefix — instead the session path replays a bounded suffix into the recurrent state (Tail-Replay) and the rollback returns "replay suffix" (a real, handled outcome), never "impossible" — the hybrid Tail-Replay gate; (6) assert the chunked-hash-tree lookup is O(1) per prefix node and low traversal CPU relative to the TTFT win (measure the lookup CPU, assert it is small) — the "cheap lookup matters more than an elegant structure" gate; (7) assert a shared block with refcount > 0 is not evicted while a session still uses it (refcounting) — the shared-and-immutable gate.

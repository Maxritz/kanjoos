# Worksheet — C23 Session scheduler and server

**What it owns:** multiple requests, and choosing which to run.

**Why it exists (from `02-components.md` — C23 section; `01` §6; `08` acceptance criteria):** an OAI/Anthropic-compatible HTTP surface (the shape Strata serves; being better means being compatible, not novel), prefix-homogeneity batching (the scheduler prefers requests that share a prefix over simply filling the batch — the shared prefix is the highest-value thing in the cache, because it is reused by construction, and it is the one object whose persistence to NVMe clearly pays — `04` §5.3), sessions carrying `{session_id, priority, prefix_hash, active_token_range, required_blocks, prefetch_deadline}` into C9/C10/C11, background maintenance (NVMe eviction, compaction, autotune writes) that never starves an active inference.

**Spec lines that must hold:**
* `02-components.md` — C23 section (verbatim: the HTTP surface, prefix-homogeneity batching, the session struct, the background-maintenance rule, the done-when).
* `04-memory-tiering.md` §5.3 (shared prefixes get a bonus in the eviction score because they are the highest-value thing in the cache: a shared prefix is reused by construction, and it is the one object whose persistence to NVMe clearly pays. C23's prefix-homogeneity batching is what produces the shared prefixes that C12/C13 persist.)
* `04-memory-tiering.md` §4 (the canonical checkpoint is read-only, read via the cold index (C4/C6); admitted KV (shared prefixes, suspended sessions after a TTL, repeatedly-reused cold segments) is what persists to NVMe. C23's shared-prefix batching is what produces the shared prefixes that are admitted to NVMe; C23's suspended sessions (after a TTL) are what C12 persists; C23's repeatedly-reused cold segments are what C12 persists.)
* `08-roadmap.md` — Acceptance criteria (concurrent sessions share prefixes and produce identical shared-span logits — the bit-identity proof for prefix sharing; a shared-prefix multi-request workload beats FIFO batching on TTFT; background compaction provably never delays a decode step).
* `09-kv-engine-architecture.md` §5 (I5 — the cache key is the full model fingerprint etc.; sessions sharing a prefix must have the same cache key (same model, arch, dtype, layout, RoPE, tokenizer, attention impl version, KV codec, impl-version) to share blocks; sessions with different keys do not share — C23's prefix_hash and session identity must include the cache key, so sessions with different models/configs/codecs do not accidentally share blocks; a cache page from a different model/config/codec is rejected, not misread.)

**Interface (from `02-components.md` C23, simplified):**
* HTTP surface: OAI/Anthropic-compatible.
* Session struct: `{session_id, priority, prefix_hash, active_token_range, required_blocks, prefetch_deadline}` — carried into C9/C10/C11.
* Batching: prefix homogeneity beats batch size for KV locality — the scheduler prefers requests that share a prefix over simply filling the batch.
* Background maintenance: NVMe eviction, compaction, autotune writes — never starves an active inference.

**Acceptance test (verbatim "done when"):**
* A mixed shared-prefix workload shows a measurable TTFT win versus FIFO batching.
* Background compaction provably never delays a decode step.

**Gates:**
* Depends on C13 (radix index — C23's prefix_hash is what C13 indexes; sessions with the same prefix_hash share blocks (if the cache key matches — I5); C23's prefix-homogeneity batching is what produces the shared-prefix hits that C13 resolves and C9/C14 serve from cache), C9/C14/C11 (residency/KV/transfer — C23's required_blocks and prefetch_deadline are what C9/C10/C11 act on; C23's active_token_range is what C9/C14 track for the session; C23's session is the unit of KV residency and prefetch), C10 (prefetch — C23's prefetch_deadline is what C10/C11 target; C23's session is what C10 predicts for and prefetches for; C23's prefix-homogeneity batching is what makes C10's prefetch effective (shared prefixes are predicted by construction)), C12 (admission/eviction — C23's shared prefixes (after they are produced by prefix-homogeneity batching) are what C12 persists to NVMe (after a TTL or on shared-prefix value); C23's suspended sessions (after a TTL) are what C12 persists; C23's session is the unit of NVMe admission), C21 (telemetry — the "mixed shared-prefix workload beats FIFO batching on TTFT" acceptance is a C21 result; C23's session state (active/inactive/suspended) and the TTFT and the shared-span logit identity are C21 numbers), C24 (platform — the HTTP surface and the server process are C24's platform; the HTTP compatibility (OAI/Anthropic) is the interface; C24 is the platform layer that hosts the server).

**Coder notes / pitfalls:**
* Prefix-homogeneity batching beats batch size for KV locality. A coder must implement the scheduler to prefer requests that share a prefix over simply filling the batch. A coder must not implement a scheduler that fills the batch by any request (FIFO or otherwise) and ignores prefix sharing — that is the "prefix homogeneity beats batch size for KV locality" rule, and it is the thing that makes the radix cache (C13) and the shared-prefix persistence (C12/NVMe) pay. The shared prefix is the highest-value thing in the cache (reused by construction, the one object whose persistence to NVMe clearly pays — `04` §5.3). A coder must design the scheduler around producing and exploiting shared prefixes, not around maximising batch size (batch size amortises weights, not KV — `01` §2.1: "Batching amortises *weights*. It does not amortise KV, because every token needs its own prefix read. Batching makes the weight term vanish and leaves the KV term untouched."). A coder must not treat batch size as the primary batching metric — prefix homogeneity is.
* The OAI/Anthropic-compatible HTTP surface. A coder must implement the HTTP surface to be compatible with OAI and Anthropic APIs (the shape Strata serves — `02-components.md` C23: "the shape Strata serves; being better means being compatible, not novel"). A coder must not invent a novel API as the primary interface — compatibility is the point (so existing clients and workflows can use the engine). A coder must implement the standard endpoints (chat completions, completions, etc.) to the OAI/Anthropic shape, and must not require clients to adopt a novel API to use the engine.
* The session struct is what C23 carries into C9/C10/C11. A coder must implement the session struct (`{session_id, priority, prefix_hash, active_token_range, required_blocks, prefetch_deadline}`) and must carry it into C9 (residency — the session's active_token_range and required_blocks are what C9 tracks and acts on), C10 (prefetch — the session's prefix_hash and prefetch_deadline are what C10 predicts for and prefetches for), and C11 (transfer — the session's required_blocks and prefetch_deadline are what C11 enqueues and targets). A coder must not drop the session struct between C23 and C9/C10/C11 — the session is the unit of state that ties the scheduler to the residency/prefetch/transfer components.
* The prefix_hash and the cache key (I5). A coder must implement the prefix_hash as part of the session, and must tie it to the cache key (I5: model fingerprint + arch + dtype + layout + RoPE config + tokenizer + attention impl version + KV codec + impl-version). Sessions with the same prefix_hash and the same cache key share blocks; sessions with the same prefix_hash but different cache keys do not share (a block from a different model/config/codec is rejected, not misread). A coder must not let sessions with different models/configs/codecs share blocks just because they have the same prefix_hash — the cache key (I5) is the guard. A coder must include the cache key in the prefix_hash or in the session's identity, so that the radix index (C13) can reject mismatched-key blocks.
* Background maintenance never starves an active inference. A coder must implement the background maintenance (NVMe eviction, compaction, autotune writes) so that it never starves an active inference — the background tasks must yield to active inference (C23's active sessions, C9's active requests, C11's in-flight transfers for active requests, C17's active GEMMs). A coder must not let background maintenance block or starve an active decode step — the acceptance test ("background compaction provably never delays a decode step") is the gate. A coder must implement the priority order (background maintenance is lower priority than active inference — C12's priority order applies here too: active inference is ACTIVE, background maintenance is lower) and the scheduling so that background tasks run only when they do not delay active inference (e.g. in gaps between steps, or at lower priority, or capped in CPU/time).
* The "mixed shared-prefix workload beats FIFO batching on TTFT" acceptance. A coder must implement a benchmark that mixes shared-prefix requests (requests that share a prefix with earlier requests) and non-shared requests, and compares prefix-homogeneity batching against FIFO batching, and asserts the prefix-homogeneity batching shows a measurable TTFT win (the shared-prefix requests get lower TTFT because their prefix is cached and batched with the earlier request that populated the cache). A coder must not claim a TTFT win without this benchmark — the acceptance test is the gate.
* Suspended sessions and TTL. A coder must implement suspended sessions (sessions that are not currently decoding but whose KV is retained) and the TTL on them (C12 persists them to NVMe after a TTL — `04` §4: "admitted KV: shared prefixes, suspended sessions after a TTL, and repeatedly-reused cold segments"). A coder must not retain suspended sessions forever — the TTL is the bound. A coder must implement the TTL and the persistence to NVMe (C12/C11/C24), and must report the suspended-session state (C21). A coder must not leak suspended-session KV forever (that would be the NVMe wear problem — C12's admission rule and the initial policy (persist suspended sessions after a TTL) are the wear-control; a coder must enforce the TTL).

**Worked micro-example (host, sanity-check before device):**
Implement a fake C23 with an OAI/Anthropic-compatible HTTP surface (fake — the shapes of the endpoints, the session struct, the scheduler), the session struct (`{session_id, priority, prefix_hash, active_token_range, required_blocks, prefetch_deadline}`), the prefix-homogeneity scheduler (prefers requests that share a prefix over simply filling the batch), and the background maintenance (NVMe eviction, compaction, autotune writes — lower priority than active inference). Then: (1) implement the prefix-homogeneity scheduler: given a mix of new requests (some sharing a prefix with earlier requests, some not), schedule the shared-prefix requests together (so their shared prefix is loaded once and shared) over filling the batch with unrelated requests — assert the shared-prefix requests get served with lower TTFT than they would under FIFO (because their prefix is cached and shared) — the "prefix-homogeneity beats FIFO on TTFT" gate; (2) implement the session struct and carry it into C9/C10/C11: assert the session's active_token_range, required_blocks, and prefetch_deadline are what C9/C10/C11 act on (C9 tracks the active_token_range and required_blocks; C10 predicts for the prefix_hash and targets the prefetch_deadline; C11 enqueues the required_blocks with the prefetch_deadline) — the "session struct carried into C9/C10/C11" gate; (3) implement the cache-key guard (I5): assert sessions with the same prefix_hash but different cache keys (different model/config/codec) do not share blocks (a block from a different key is rejected, not misread) — the "cache key guards prefix sharing (I5)" gate; (4) implement suspended sessions and TTL: assert a suspended session's KV is retained for the TTL and then persisted to NVMe (C12/C11/C24) and the TTL is enforced (suspended sessions do not leak forever) — the "suspended sessions and TTL" gate; (5) implement background maintenance (NVMe eviction, compaction, autotune writes) at lower priority than active inference, and assert it never delays an active decode step (the background tasks yield to active inference; a decode step never waits for background maintenance) — the "background maintenance never starves active inference" gate; (6) implement the TTFT benchmark: run a mixed shared-prefix workload under prefix-homogeneity batching and under FIFO batching, and assert the prefix-homogeneity batching shows a measurable TTFT win for the shared-prefix requests (their TTFT is lower because their prefix is cached and shared) — the "mixed shared-prefix workload beats FIFO on TTFT" gate.

# Worksheet — C14 KV cache engine

**What it owns:** the paged KV the attention kernels read.

**Why it exists (from `02-components.md` — C14 section; `09` §5; `04` §6):** the KV cache is paged, with layer slabs (2 layers on 6 GiB, 4 on 8/12/16 GiB), a block table per session, physical blocks from the WARM pool or NVMe, and geometry computed from the loaded config (never hard-coded: `bytes/token = 2 × layers × kv_heads × head_dim × sizeof(codec)`).
  The attention path only ever sees VRAM-resident KV pages — the planner (C9/C10/C11) guarantees a RAM page has landed before attention, or the CPU path is taken. Recurrent layers keep a separate state array with its own budget and residency (fixed-size state per layer, not paged — `04` §6).

* `09-kv-engine-architecture.md` §5 (I4: no synchronous NVMe read on the critical path — the attention path only ever sees VRAM-resident KV; the planner guarantees a RAM page has landed before attention, or the CPU path is taken. I7: a KV page survives eviction and reload bit-identically. I5: the KV cache identity includes the full model fingerprint etc.)
* `04-memory-tiering.md` §6 (KV has its own index (C13) and its own tiers, sharing C9's machinery; block size 16 tokens (6 GiB) / 32 tokens (8/12/16 GiB); layer slabs 2 (6 GiB) / 4 (8/12/16 GiB); recurrent state not paged — fixed-size state per layer with its own budget line;
  mixed-precision, not mixed-format — one codec per page, chosen by tier default, recorded in the key; recompute is the fallback of last resort, and KV_RECOMPUTE_RATE is a primary KPI).

**Interface (from `02-components.md` C14, simplified):**
* Address: `(model_id, layer_start, layer_count, token_start, token_count, kv_format)`.
* Layer slabs: a decode layer consumes one layer's K/V; paging all 48 layers to serve one wastes the transfer. Slab = 2 layers on 6 GiB, 4 on 8/12/16 GiB.
* Block table per session; physical blocks from the WARM pool or NVMe.
* Geometry computed from the loaded config, never hard-coded: `bytes/token = 2 × layers × kv_heads × head_dim × sizeof(codec)`.

**Acceptance test (verbatim "done when"):**
* A KV page survives eviction and reload bit-identically (I7).
* Context length scales to the profile's ceiling with the reported residency label (VRAM-resident / RAM-resident / storage-assisted / storage-bound).

**Gates:**
* Depends on C9 (residency — C14's KV pages are what C9 places; C9's `ready()` for a KV page is "the block has landed in VRAM"; the planner (C9/C10/C11) guarantees a RAM page has landed before attention, or the CPU path is taken — C14's attention kernel asks C9's `ready()` for each KV block it needs, and never blocks),
  C11 (transfer — C14's KV pages are moved by C11 (NVMe→RAM→H2D); C14's attention kernel never issues a storage read — C11/C9 do that asynchronously before the layer arrives), C13 (radix index — C14's KV blocks are the physical blocks C13 maps prefixes to; C14 is the block-id→physical-block side, C13 is the prefix→block-id side),
  C15 (KV codecs — C14's KV pages are stored in a codec (FP8 on gfx1201, FP16/BF16 on gfx1031, TurboQuant 4bit-nc behind a gate); the codec is part of the key; a page written as FP8 is never read as BF16; C14's block format is what C15 provides),
  C21 (telemetry — KV_RECOMPUTE_RATE is a C21 KPI; the residency label is a C21 output; the "context length scales to the profile's ceiling with the reported residency label" is a C21 result), C22 (budget — the block size, layer slab, and KV budget come from C22's profile; C14's geometry is what C22 sets),
  C19 (fallback — if a KV page is not ready when its layer arrives, the planner has already taken the CPU/expert fallback (C19) rather than stalling; C14's attention kernel never waits on a KV page — it asks C9's `ready()` and the scheduler has already failed over if false).

**Coder notes / pitfalls:**
* The attention path only ever sees VRAM-resident KV pages. This is the hard invariant (I4: no synchronous NVMe read on the critical path). A coder must not let the attention kernel read a KV page that is in RAM or NVMe — the page must have landed in VRAM before the layer arrives (the planner C9/C10/C11 guarantees this, or the CPU path is taken).
  The attention kernel asks C9's `ready()` for each KV block it needs; if any is not ready, the scheduler has already failed over (not the kernel stalling). A coder must not implement "attention kernel waits for KV page to arrive" — that is the synchronous-NVMe-read-on-the-critical-path failure.
* Layer slabs, not one-layer-per-page. A decode layer consumes one layer's K/V; paging all 48 layers to serve one token wastes the transfer. A coder must implement layer slabs (2 layers on 6 GiB, 4 on 8/12/16 GiB — from C22's profile) as the paging granularity for decode, so a decode step reads one slab (2 or 4 layers) of KV, not all 48 layers. A coder must not page each layer independently for decode — that is the "paging all 48 layers to serve one wastes the transfer" failure.
* Geometry from config, never hard-coded. A coder must compute `bytes/token = 2 × layers × kv_heads × head_dim × sizeof(codec)` from the loaded config (layers, kv_heads, head_dim from the config; codec from C15), and must refuse (exit 2/3/4, same as `kv_roofline.py`) when the config is missing a field it needs.
  A coder must not hardcode 48/4/128 — the same component on a different model (e.g. a windowed-attention model, a cross-layer-KV-sharing model) has different geometry, and the tool's refusal semantics apply. (The Qwen3-30B-A3B config gives 98,304 B/token FP16 — `kv_roofline.py` section B — and that is the number the geometry must reproduce.)
* KV_RECOMPUTE_RATE is a primary KPI. A coder must be able to measure and report the rate at which KV pages are recomputed (rather than served from cache) — this is the signal that the warm tier is too small. A coder must not hide recompute behind a "we served it from somewhere" accounting — a recomputed KV page is a miss that was cheaper to recompute than to fetch, and it is a measurable rate, not a hidden event.
* Recurrent layers are separate. A coder must keep recurrent-layer state separate from the paged KV (recurrent state is a fixed-size state per layer with its own budget and residency, and is not paged — `04` §6). A coder must not page recurrent state as if it were token-addressable KV — it is not; it is a per-layer fixed-size state.
* Mixed-precision, not mixed-format. One codec per page, chosen by tier default, recorded in the key. A coder must not mix codecs within a page, and must record the codec in the block's key (so a page written as FP8 is never read as BF16 — I5). A coder must support the tier-default codec per arch (FP8 on gfx1201, FP16/BF16 on gfx1031) and TurboQuant 4bit-nc behind a quality gate (opt-in, not default).

**Worked micro-example (host, sanity-check before device):**
Implement a fake C14 with layer slabs (2/4 layers per slab from C22's profile), a per-session block table, physical blocks from a fake warm pool or fake NVMe, geometry computed from a fake config (layers/kv_heads/head_dim from config, codec from C15), and a fake C9 (residency — `ready()` per KV block; the planner guarantees a RAM block has landed before attention, or the CPU path is taken). Then: (1) compute `bytes/token = 2 × layers × kv_heads × head_dim × sizeof(codec)` from the config and assert it matches `kv_roofline.py` section B (Qwen3-30B-A3B → 98,304 B/token FP16) — the geometry-from-config gate; (2) implement layer-slab paging for decode: a decode step reads one slab (2 or 4 layers) of KV blocks, not all 48 layers — the layer-slab gate; (3) implement the attention-kernel-reads-only-VRAM-resident rule: the attention kernel asks C9's `ready()` for each KV block it needs, and if any is not ready, the scheduler has already failed over (CPU path) — never does the attention kernel wait on a RAM/NVMe block — the I4 gate; (4) implement eviction + reload of a KV block and assert the reloaded block is bit-identical to the original (I7) — the KV-page-survives-evict-reload-bit-identically gate; (5) implement the residency label reporting (VRAM-resident / RAM-resident / storage-assisted / storage-bound) and assert context length scales to the profile's ceiling with the reported label (a run at the ceiling reports the label that matches where the KV actually is) — the context-length-scales-with-residency-label gate; (6) implement KV_RECOMPUTE_RATE as a measurable, reported KPI (a recomputed KV page is a miss that was cheaper to recompute than to fetch, and it is reported, not hidden) — the KV_RECOMPUTE_RATE-KPI gate; (7) implement recurrent layers as a separate fixed-size-per-layer state with its own budget and residency, not paged as token-addressable KV — the recurrent-separate-state gate; (8) implement mixed-precision (one codec per page, chosen by tier default, recorded in the key) and assert a page written as FP8 is never read as BF16 (I5) — the mixed-precision-not-mixed-format gate; (9) implement TurboQuant 4bit-nc as opt-in behind a quality gate (not default) — the TurboQuant-behind-a-gate gate.
